# Database

PostgreSQL on Supabase (EU region, owner decision R-01), accessed with Drizzle ORM. Schema: `lib/db/schema.ts`. Migrations: `drizzle/`.

> **Status:** the migrations have **not been applied to any Supabase project**. They were applied and tested only against local, in-process PostgreSQL (PGlite) with a Supabase stub (`tests/db`). Applying them to a shared project requires owner approval (R-02).

## Tables

| Table | Purpose | Notes |
|---|---|---|
| `profiles` | 1:1 with `auth.users`; holds `role` (`customer`, `staff`, `admin`) | Created by trigger on sign-up. Role changes only via `admin_set_user_role()` |
| `customers` | Contact details of whoever requested a quote; `user_id` links to a login | Email deliberately **not unique**: anonymous requests are never auto-linked to accounts by email |
| `quote_requests` | Requests (`QR` + 6 base32) with service code, route, JSONB `items`, status, locale | `items` must be a JSON array of 1–50 entries, ≤ 32 KB; service-specific shape validated by Zod |
| `quotes` | Staff-entered quotes: `amount_minor` (integer), `currency` (`EUR`, `XAF`), validity, inclusions/exclusions | Frozen once `sent_at` is set |
| `shipments` | `ML` + 10 base32 reference; owner and service derived from the accepted quote | ETA shown to customers only if `eta_visible` |
| `shipment_events` | Milestone code, location, time, EN/FR notes, `public` flag | Non-public events are internal working notes |
| `documents` | Metadata for private files in the `customer-documents` bucket | `retention_until` stays NULL until a policy is approved (L-03) |
| `audit_log` | Append-only change history | Written only by triggers/definer functions |
| `rate_limits` | Fixed-window counters | **Why:** serverless instances do not share memory; keys are hashed |
| `email_deliveries` | Transactional email log | **Why:** report "sent" only when the provider accepted, and make retries idempotent |

Money uses integer minor units with an ISO 4217 code (EUR has 2 decimals, XAF has 0). Delete rules are `RESTRICT` for business, financial, shipment and audit history; only `profiles` follows its auth user.

## Quote lifecycle

```
SUBMITTED -> UNDER_REVIEW -> AWAITING_CUSTOMER -> QUOTED -> ACCEPTED | DECLINED | EXPIRED
             UNDER_REVIEW -> QUOTED                (staff can quote without asking for more information)
        AWAITING_CUSTOMER -> UNDER_REVIEW          (review resumes after the customer replies)
        AWAITING_CUSTOMER -> QUOTED                (information received by phone/email)
any status except CANCELLED -> CANCELLED           (reason required, 1–500 characters)
```

- The table lives in `lib/domain/quote-lifecycle.ts` **and** in `app_quote_transition_allowed()`; a test checks every pair is identical.
- The trigger `app_enforce_quote_request_rules` rejects any other change, requires a **sent** quote for `QUOTED` and a **still-valid** quote for `ACCEPTED`, and blocks edits to identity fields.
- Who may do what: staff/admin for review and cancellation (RLS `quote_requests_staff_update`); the owning customer for accept/decline through `customer_respond_to_quote()`; `EXPIRED` only through `app_expire_quotes()` (server or scheduled job).
- Every change writes an `audit_log` row **in the same transaction** (`app_audit_row` trigger), so a status change can never succeed without its audit record.

## Access model (Row Level Security)

| Role | Access |
|---|---|
| `anon` | No table privileges at all. Only `public_track_shipment(text)` |
| `authenticated` customer | Own `customers` row, own requests, **sent** quotes, own shipments, **public** events, own documents. Column grants hide `created_by`, `uploaded_by`, `storage_key`, `submitted_by`, `idempotency_key` |
| `authenticated` staff/admin | All operational records; inserts/updates allowed by policy; audit log read |
| admin only | `admin_set_user_role()` (cannot remove the last admin) |
| `service_role` | Bypasses RLS. Used server-side only for Storage and invitations, always after application checks |

- Helper functions (`app_current_role`, `app_is_staff`, `app_is_admin`, `app_owns_customer`) are `SECURITY DEFINER` with `search_path = ''`, so policies never recurse.
- The app runs user-facing queries **as the `authenticated` role with the user's JWT subject** (`withUser()` in `lib/db/context.ts`). RLS therefore protects the app's own queries, not just the public API.
- The privileged connection (`withSystem()`) is used only for anonymous quote submission, rate limiting, email logging and reads that already passed an RLS check.

## Migrations

| File | Content |
|---|---|
| `0000_initial_schema.sql` | Generated by `drizzle-kit generate`, reviewed: enums, tables, checks, FKs, indexes |
| `0001_security_model.sql` | Hand-written, idempotent (`create or replace`, `drop … if exists`): functions, triggers, RLS, grants, private bucket (only if the `storage` schema exists) |

Rules:
- Generate with `npm run db:generate`. **Never** use `drizzle-kit push`.
- Review generated SQL before committing. Migrations must not contain destructive statements; a test enforces this.
- Apply with `npm run db:migrate` (`scripts/db-migrate.mjs`, uses `DIRECT_URL`). It **refuses any non-local host** unless `ALLOW_MIGRATE_HOST` equals that host. Set it only after the owner has approved the SQL (R-02).
- Re-running is safe: the Drizzle migrator records applied files in `drizzle.__drizzle_migrations`, and 0001 is itself idempotent (both are tested).

### Applying to Supabase after approval (R-02)
1. Create the project in the approved EU region. Note the **direct** connection string (port 5432) and the **pooled** one (port 6543).
2. Review `drizzle/0000_initial_schema.sql` and `drizzle/0001_security_model.sql`.
3. Run `DIRECT_URL=… ALLOW_MIGRATE_HOST=<db host> npm run db:migrate`.
4. Bootstrap the first administrator in the Supabase SQL editor (trusted path):
   ```sql
   begin;
   select set_config('app.role_change', 'allowed', true);
   update public.profiles set role = 'admin' where id = '<auth user uuid>';
   commit;
   ```
5. Schedule `select public.app_expire_quotes();` (for example hourly with `pg_cron`) so expired quotes move to `EXPIRED`.

## Seed (local only)
`npm run db:seed` creates fictitious users (`demo.*@example.test`) and demo records in every workflow stage. It refuses non-local `SUPABASE_URL`/`DIRECT_URL`. The seed logic (`scripts/seed-data.ts`) is executed in tests against PostgreSQL.

## Test coverage (executed)
`tests/db/*.test.ts` run against PGlite (PostgreSQL 17 in WebAssembly) with `tests/db/supabase-stub.sql`, which emulates `auth.users`, `auth.uid()`, the API roles and Supabase's default grants. They cover migrations, all ten required RLS/authorisation cases, lifecycle, audit, constraints, references, rate limiting and the seed. A final confirmation against a real Supabase stack (`supabase start`) is still to be done; see [TESTING.md](./TESTING.md).
